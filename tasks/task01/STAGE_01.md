Ты работаешь с существующим репозиторием Python-библиотеки `yandex-direct-api-client`.

## Цель проекта

Превратить текущий проект в качественную, расширяемую и пригодную для повторного использования Python-библиотеку для работы с Yandex Direct API v5.

Исходные требования:

* Python 3.12.6+;
* основной интерфейс — синхронный;
* библиотека должна быть пригодна для использования в разных проектах;
* допускается серьёзная переработка существующей архитектуры;
* MCP сейчас не нужен;
* AI сейчас не нужен;
* автоматическая оптимизация рекламных кампаний сейчас не нужна;
* генерация рекламных текстов сейчас не нужна;
* клиент должен только предоставлять удобный и надёжный API для работы с Yandex Direct;
* в будущем отдельный проект сможет использовать этот клиент для автоматической оптимизации рекламы;
* не нужно реализовывать весь Yandex Direct API целиком только ради полноты;
* сначала нужны наиболее полезные и устойчивые возможности, затем библиотеку можно расширять.

## Публичный API

Продумай удобный интерфейс библиотеки.

Например, концептуально:

```python
client.campaigns.list(...)
client.campaigns.get(...)
client.campaigns.create(...)
client.campaigns.update(...)
client.campaigns.delete(...)

client.ads.list(...)
client.ads.get(...)
client.ads.create(...)
client.ads.update(...)
client.ads.delete(...)
```

Это пример направления, а не обязательный API.

Определи структуру самостоятельно.

Существующий API разрешено серьёзно изменить, если это действительно улучшает библиотеку.

Но не ломай существующие методы бессмысленно.

Если обнаружишь необходимость breaking changes, зафиксируй это в отчёте.

## Модели

Используй типизированные Python-модели.

Проанализируй существующие dataclasses и реши, стоит ли сохранить этот подход или изменить его.

Пользователь библиотеки должен по возможности работать с нормальными Python-объектами, а не с сырыми JSON-словарями.

Например:

```python
campaign.id
campaign.name
campaign.state
```

вместо постоянного использования:

```python
campaign["Id"]
campaign["Name"]
campaign["State"]
```

Не добавляй тяжёлые зависимости без необходимости.

## Безопасные изменения

Сохрани и улучши механизм `readonly`.

Определи единый способ защищать операции изменения данных.

Потенциально опасные операции должны требовать явного подтверждения.

Особенно:

* delete;
* массовые изменения;
* потенциально необратимые операции.

Механизм должен быть понятным и предсказуемым.

Например:

```python
client.ads.delete(..., confirm=True)
```

Но окончательный интерфейс выбери сам.
