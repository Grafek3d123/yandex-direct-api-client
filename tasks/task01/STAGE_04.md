Продолжай работу над `yandex-direct-api-client`.

Этапы 1–3 должны быть завершены.

Теперь нужно довести библиотеку до состояния качественного переиспользуемого Python-пакета.

На этом этапе основной фокус — качество, стабильность, документация и устранение проблем.

Не нужно бесконечно добавлять новые возможности Yandex Direct.

## Цель

Проверить, что библиотека:

* логична;
* стабильна;
* удобна;
* типизирована;
* протестирована;
* документирована;
* расширяема;
* не содержит ненужного дублирования;
* не перегружена архитектурными абстракциями.

## Полный аудит

Проверь:

1. публичные импорты;
2. публичный API;
3. модели;
4. HTTP transport;
5. authentication;
6. ошибки;
7. retry;
8. rate limiting;
9. batching;
10. readonly;
11. confirmation для опасных операций;
12. основные ресурсы;
13. статистику;
14. тесты;
15. package metadata;
16. README;
17. type hints;
18. документацию;
19. changelog или migration notes.

## Дублирование

Найди и устрани повторяющуюся логику.

Особенно проверь:

* HTTP requests;
* retry;
* error handling;
* JSON conversion;
* chunking;
* readonly;
* confirmation.

Не должно быть нескольких разных реализаций одного и того же поведения без необходимости.

## Публичный API

Проверь удобство использования библиотеки.

Пользователь не должен импортировать внутренние классы ради стандартных операций.

Например:

```python
from yandex_direct_api_client import ...
```

должно быть достаточно для обычных сценариев.

Внутренние реализации не должны случайно становиться частью публичного API.

если проблему можно устранить корректно.

## Безопасность

Проверь:

* нельзя ли случайно выполнить delete;
* нельзя ли случайно выполнить массовое изменение;
* корректно ли работает readonly;
* действительно ли требуется confirmation;
* не попадают ли токены в логи;
* нет ли секретов в репозитории;
* не теряется ли чувствительная информация в исключениях.
