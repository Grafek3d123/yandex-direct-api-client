Продолжай работу с `yandex-direct-api-client`.

Этапы 1 и 2 должны быть завершены.

Этот этап посвящён статистике и отчётам Yandex Direct.

Статистика особенно важна, потому что позже отдельный проект-оптимизатор будет использовать клиент как источник данных.

Но сам клиент **не должен принимать маркетинговые решения**.

## Цель

Сделать работу с отчётами полноценной, типизированной и расширяемой.

Не ограничивайся одним упрощённым методом:

```python
client.get_stats(...)
```

Нужно предусмотреть работу с различными:

* периодами;
* датами;
* сущностями;
* измерениями;
* метриками;
* группировками;
* фильтрами;
* сортировками;
* уровнями детализации.

Конкретный API выбери на основании официальной документации Yandex Direct.

## Публичный интерфейс

Интерфейс должен быть понятным.

Например, допустим такой подход:

```python
client.reports.get(...)
```

Но это только пример.

Определи итоговую структуру сам.

Не делай один огромный метод с десятками неочевидных аргументов.

Пользователь должен иметь возможность явно задавать:

* начало периода;
* конец периода;
* сущности;
* поля;
* метрики;
* фильтры;
* сортировку;
* детализацию.

## Типизация

Продумай типизацию для:

* параметров отчёта;
* периода;
* измерений;
* метрик;
* строк отчёта;
* статуса отчёта;
* ошибок.

Не превращай абсолютно всё в `dict[str, Any]`.

Одновременно не пытайся искусственно статически описать все возможные динамические комбинации отчётов.

Нужен разумный баланс между типизацией и гибкостью.

## Асинхронные отчёты

Учитывай механизм Yandex Direct, при котором отчёт может некоторое время находиться в состоянии подготовки.

Корректно реализуй:

1. отправку отчёта;
2. ожидание готовности;
3. повторный запрос;
4. timeout;
5. retry;
6. `429`;
7. ошибки;
8. возврат готового результата.

Не дублируй retry-логику в отдельных местах.

## Масштабирование

Продумай:

* большие диапазоны дат;
* большие списки идентификаторов;
* chunking;
* несколько запросов;
* API limits;
* rate limiting.

При необходимости библиотека должна уметь разбивать слишком большие запросы.

## Поисковые запросы и конверсии

Добавь возможности, которые реально нужны для получения данных о:

* поисковых запросах;
* конверсиях;
* целях;
* показателях эффективности.

Сверяй конкретные методы и поля с официальной документацией Yandex Direct.

## Разделение ответственности

Клиент возвращает данные.

Он не должен сам решать:

```python
disable_bad_keywords()
```

или:

```python
raise_bid_for_good_ads()
```

Такая логика появится позднее в отдельном проекте.

## Результаты

Результаты статистики должны быть удобны для:

* обычного Python;
* последующего анализа;
* pandas;
* JSON;
* CSV;
* передачи в другие системы.

Pandas не должна становиться обязательной зависимостью базовой библиотеки без явной необходимости.
