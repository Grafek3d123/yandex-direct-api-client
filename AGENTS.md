# AGENTS.md — правила для ИИ-агента

Этот файл — жёсткий контракт поведения ИИ-агента (Koda, Copilot, Cursor, и т.п.)
при работе в репозитории `yandex-direct-api-client`.

## 1. Git — строгие запреты

- **НЕ делать `git commit` без явного указания пользователя в текущем сообщении.**
  Подтверждение в предыдущих сообщениях диалога НЕ считается разрешением.
- **НЕ делать `git push` без явного указания пользователя в текущем сообщении.**
- **НЕ делать `git reset`, `git rebase`, `git checkout -- .`, `git restore`,
  `git clean`, `git stash drop`** — это разрушающие операции.
- **НЕ менять историю коммитов** (amend, filter-branch, force-push).
- Если задача требует git-мутации — явно попросить пользователя подтвердить
  конкретной командой, которую нужно выполнить.

## 2. Область изменений

- Работать **только внутри** `ydirect-api-client/`.
- **НЕ трогать** соседний проект `../YandexDirectHelper/` (включая `ad_optimizer/`).
  Он используется только как референс для переноса логики.
- **НЕ менять** `pyproject.toml`, `AGENTS.md`, `LICENSE` без явного согласования.
- **НЕ создавать** новые файлы вне `ydirect-api-client/` без явного запроса.

## 3. Код и стиль

- Python ≥ 3.9. Все публичные функции и методы — **полностью типизированы**.
- Соблюдать `ruff` и `mypy --strict`. Перед завершением задачи прогнать:
  ```bash
  ruff check .
  mypy yandex_direct_api_client
  pytest
  ```
  Все три должны пройти без ошибок.
- Строки docstring — на русском для публичных API, на английском — для внутренних.
- Не добавлять комментарии в код без необходимости.
- Не использовать `print()`. Только `logging.getLogger(__name__)`.
- Не использовать `assert` для runtime-валидации (assert выключается с `-O`).

## 4. Зависимости

- **НЕ добавлять** новые runtime-зависимости без обоснования.
- Если новая зависимость нужна — добавить в `[project.optional-dependencies]`,
  не в основные.
- Перед добавлением проверить, что она не тянет конфликтов с `requests`.

## 5. Тесты

- Каждый новый публичный метод `YandexDirectClient` обязан иметь unit-тест
  в `tests/` с mock HTTP (библиотека `responses`).
- Реальные HTTP-запросы в тестах **запрещены**.
- Не удалять существующие тесты без явного согласования.

## 6. Изменения публичного API

- Любое изменение сигнатур публичных методов — **breaking change**.
  Требует bump MAJOR версии и запись в `CHANGELOG.md`.
- Добавление новых опциональных параметров — minor bump + запись в `CHANGELOG.md`.

## 7. Безопасность

- **НИКОГДА** не логировать токены, refresh-токены, client_secret.
- **НИКОГДА** не сохранять токены в git (см. `.gitignore`).
- При отладке использовать `token[:4] + "..."` вместо полного значения.

## 8. Формат коммитов (когда пользователь явно разрешил)

Conventional Commits: `feat:`, `fix:`, `chore:`, `docs:`, `refactor:`, `test:`.

## 9. Коммуникация

- Отвечать на русском, если пользователь пишет на русском.
- Если задача неоднозначна — задать уточняющий вопрос **до** изменений в коде.
- После каждого набора изменений кратко резюмировать: что изменено, какие тесты
  запущены, что сломано/не сломано.
